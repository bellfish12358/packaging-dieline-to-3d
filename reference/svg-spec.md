# 刀版 SVG 结构与解析约定

> 以 `scripts/build_box.py` 的实际实现为准。本文不是「理想格式」，是「当前脚本真能吃进去的格式」。

## 1. 文件层面

- 单位 **mm**，1:1 实尺
- 脚本直接使用 SVG 原始坐标，**不做单位换算**
- **不支持 `transform`**；有 transform 时坐标会错
- **不应用 `viewBox` 缩放**；请确认坐标本身已经是最终 mm 坐标
- 只含两类线：刀线与折线
- 常见导出：包小盒、Illustrator、CAD 转 SVG

## 2. 线怎么分

脚本**不看颜色、不看虚线样式**，只认 group id：

| 类型 | 当前识别规则 |
|---|---|
| 刀线 | `<g id="cut">` 下的直接 `<path>` 子元素 |
| 折线 | `<g id="fold">` 下的直接 `<line>` 子元素 |

注意：

- group id 大小写不敏感（`CUT` / `Cut` 也认），但必须是 `cut` / `fold`
- 只读**直接子级**；嵌套 group 里的路径/线会被忽略
- 折线不能用 `<path>`；刀线不能用 `<polygon>` / `<rect>`
- 没有 `cut` / `fold` group → 解析出 0 片，必须停下来问，不要猜

> 旧文档说「虚线或蓝色描边都能识别」，这是设计目标；当前脚本没有实现。`preflight.py` 会先检查 group。

## 3. 刀线路径

- 每条 `<path>` 必须是一个**闭合轮廓**，对应一块面片
- 不要一条 path 里放多个子路径（多个 `M`）；脚本会把它们连成一条多边形
- 支持的命令：`M / L / H / V / A / Z`（绝对与相对）
- **不支持 `C / S / Q / T`** 三次/二次贝塞尔；圆角请用 `A` 弧线导出
- 不做面积过滤：面积很小的噪点也会被当成面片，输入前先清掉
- 脚本不检查自交；自交路径会导致面片/UV 异常，输入前要保证简单多边形

## 4. 折线与邻接

### 4.1 分离刀版（面片已经分开，留 2mm 缝）

折线画在缝里，配对条件（`build_adjacency_gapped`）：

1. 折线与两侧面片的折边基本平行：方向余弦 > 0.85
2. 折线到两侧折边的距离 < 1.8 mm（`gap × 0.9`）
3. 折线与折边的投影重叠 ≥ 折线长度的 45%
4. 折线两侧的面片重心分居折线两侧

满足后得到邻接三元组：`(面片A, 面片B, 折轴)`；折轴走缝中线。

分离刀版**不要求**折线端点正好落在面片顶点上。

### 4.2 连体刀版（面片相接，折线在公共边上）

1. `split_faces` 沿折线弦把闭合轮廓切开
2. 折线端点必须落在面片顶点上（容差 `1e-4` mm）
3. 切开后 `build_adjacency` 用折线中点找两侧面片
4. 再沿折痕边各收 1 mm，形成 2 mm 缝；自由边不动

如果折线端点不在顶点上，`split_poly` 会返回原多边形，切分失败。

### 4.3 分流规则

脚本对两种输入都各算一次：

```text
edges_gap   = 分离刀版的配对结果
edges_split = 连体刀版切分后的配对结果
```

选「匹配折线更多」的那条：

- `edges_gap == 全部折线` → `separated`
- `edges_split == 全部折线` → `connected`
- 否则取匹配数更多的；仍相同则按面片数是否增加判断
- 一条都没配上 → 报错，不继续

## 5. 折叠树

1. 选**面积最大的面片**作为根（基准面，固定不动）
2. 从根 BFS 展开，每个节点记录父面片、折轴、角度
3. 折向：每条折边试 `+90°` 和 `-90°`，选让子面片重心更低的那一个
4. `M[child] = M[parent] @ R`
5. 求解后检查所有面片是否都拿到变换；缺一个就报错，不继续渲染

当前不做「首尾闭合残差」数值校验；闭合靠 clay 目检。

## 6. 折向

默认规则：**印刷面朝外**。

- 所有面片建面时法向朝 `+Z`
- 折向由「子面片重心向下」自动选择，不是显式的山折/谷折输入
- 这个规则对凸的管式盒有效；异形盒/凹盒可能不成立
- 刀版本身不含折向信息；第一次跑新盒型必须让人看 clay 或折向图确认

## 7. 建模参数

| 项 | 值 |
|---|---|
| 面片间隙 | 2.0 mm |
| 纸厚 | 0.5 mm，Solidify 向盒内 |
| 倒角 | 0.5 mm / 3 段 / 角度限制 40° |
| 折叠角 | 90°（全局） |
| 折痕模式 | `USE_CREASE_BAND=True`：窄 V 槽，深 0.25 mm |
| 平滑 | 自动平滑 30° |
| 合并 | join 后 `remove_doubles(1e-5)`，不焊接 2mm 缝 |

## 8. UV

- 每块面片的 UV 直接取它在 SVG 中的平面坐标
- 按整张刀版的包围盒归一化到 0–1
- **Y 轴翻转**：SVG 的 Y 向下，UV 的 Y 向上
- 每块面片是一个独立 UV 岛，岛与岛相对位置与刀版一致
- 不做自动展开、不重新排布
- 当前在 `make_mesh` 建面时写入；`setup_uv()` 是遗留函数，主流程没有调用

## 9. 报告里应该有的解析数据

`report.json` 当前包含：

- `mode`：`separated` / `connected`
- `contours_from_svg`：原始闭合轮廓数
- `faces_after_split`：切分后的面片数
- `pieces_from_svg`：实际建模面片数（兼容字段）
- `folds_in_svg`：输入折线数
- `fold_count` / `folds_matched`：成功配对数
- `folds_unmatched`：未配对数
- `faces_in_tree`：实际进树面片数
- `root_face`
- `size_mm`
- `params`：paper / bevel / fold / gap / crease mode / crease depth
- `warnings`

必须满足：

```text
folds_unmatched == 0
faces_in_tree == pieces_from_svg
```

否则不要继续渲染。

## 10. 当前不支持的输入

| 输入 | 处理 |
|---|---|
| 无 cut/fold group | 停下来问，或人工整理 |
| C/S/Q/T 曲线 | 导出前转成折线/圆弧 |
| transform | 导出时应用变换 |
| polygon/rect | 转成 path |
| 多子路径 path | 拆成多条 path |
| 小噪点轮廓 | 输入前删掉 |
| 盘式盒/天地盖/异形盒 | 超出范围，说明后停止 |
| 非 90° 折角/开盖姿态 | 当前不支持逐折角度 |

## 11. 连体刀版的切分诊断（v2 新增）

`split_faces` 现在为每条折线留一条日志，写进 `report.json` 的 `split_log`：

```json
{"fold": 11, "a": [294.0, 324.0], "b": [294.0, 426.0],
 "faces_before": 12, "faces_after": 13, "split": 1,
 "reason": "ok", "detail": 0.0}
```

| reason | 含义 | 怎么办 |
|---|---|---|
| `ok` | 切开了N片 | 正常 |
| `shared_edge` | 两条轮廓的公共边，本来就不用切 | 正常，不是错误 |
| `no_start_vertex` / `no_end_vertex` | 端点没落在面片顶点上，`detail` = 最近顶点距离 mm | 把端点吸附到顶点，或导出前打断边 |
| `crosses_chord` | 面片跨在折线两侧（折线中段有缺口、端点不在边上） | 折线改成落在边界的直线段 |
| `zero_area` / `degenerate` | 切出来一侧面积为 0 或环退化 | 查重复点、自交 |

`preflight.py` 也会先算 `fold_endpoint_max_dev_mm`（端点离最近顶点多远）、`self_intersections`、`min_contour_area_mm2`，在启动 Blender 前就能发现大部分问题。
